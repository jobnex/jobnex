# Strawberry Jobs — Project Reference

A Next.js job-search platform with a public **Job Board** and a personalized **Job Hunt** workspace. Data is currently mock/in-memory (no database).

| Area | Choice |

## Backend logic — `app/api/jobs/route.ts`

`GET` reads query params and filters `jobsData` (from `data/jobs.ts`):

| Param | Behavior |
|---|---|
| `keyword` | substring match on title / company / description |
| `location` | region-aware: `us`/`uk`/`in` expand to city/state keyword sets; otherwise plain substring |
| `categories` | comma-separated; `matchesDomain()` does semantic text matching over title+description+company+categories per domain id |
| `type` | exact match on `job.type` |
| `seniority` | `matchesSeniority()` — title/jobType keyword heuristics (`entry` / `mid` / `senior` / `lead`) |
| `minSalary` | `parseSalaryAmount()` normalizes `$/hr`, `/day`, `£k`, `$k`, `₹L` to a rough annual USD figure |
| `postedTime` | `1h` / `12h` / `24h`(`1d`) / `7d`(`1w`); `parsePostedHours()` reads `getJobPostedTime()` |
| `visaSponsorship` | `sponsored` — excludes "no visa"/"citizens only", heuristically includes full-time/remote/$ or £ salaried roles |
| `page`, `limit` | when `page` present → paginated `JobsResponse` (default limit 12); else unpaginated fallback |

Response shape: `JobsResponse` = `{ jobs, total, page, limit, totalPages, hasNextPage, hasPrevPage }`.

## State — `store/useJobStore.ts` (Zustand)

Holds **all Job Board filter state**: `searchQuery`, `location` (default `"United States"`), `categories[]`, `jobType`, `seniority`, `minSalary`, `postedTime`, `visaSponsorship`, `page`, plus modal state (`isModalOpen`, `selectedJob`) and `isFilterMenuOpen`.

Conventions:
- Every filter setter resets `page` to `1`.
- Setters are toggles — passing the current value (or `"all"`) clears that filter.
- `resetFilters()` clears everything except `location`.

The Job Board page (`app/(main)/page.tsx`) subscribes to this store and builds the React Query key/params from it. The Job Hunt page uses its **own local `useState`**, not this store.

## Types & constants

- `types/job.ts` (re-exported via `types/index.ts`): `Job`, `JobType`, `SeniorityLevel`, `JobBadge`, `JobFilterParams`, `JobsResponse`, `FilterOption`, `LocationOption`.
- `lib/constants/filters.ts`: `DOMAIN_OPTIONS`, `JOB_TYPE_OPTIONS`, `SENIORITY_OPTIONS`, `POSTED_TIME_OPTIONS`, `VISA_OPTIONS`, `LOCATION_OPTIONS`.
- `lib/auth-schemas.ts`: Zod schemas for auth.
- `lib/utils.ts`: `cn`, `getJobPostedTime`, `maskEmail`, salary/time helpers.
- `lib/hooks/useDebounce.ts`: generic debounce (used at 400ms for search).

## Data

- `data/jobs.ts` — hardcoded `jobsData: Job[]`, multi-region locations and multi-currency salary strings (`$120k - $150k`, `$80/hr`, `₹28L - ₹40L`, `£90k - £120k`, …). Also exposes `getCuratedPartition()` and `getJobPostedTime` usage.
- `data/sample-resume.ts` — sample resume content for the resume modal.

## Notable behaviors

- Search is debounced 400ms on both Job Board and Job Hunt.
- React Query: `placeholderData: keepPreviousData`, `refetchOnWindowFocus: false`, `staleTime: 5min`.
- Job Board scrolls to top on filter change and on bottom-pagination page change (`app/(main)/page.tsx` refs + effects).
- Auth flow is presentational only — no real code sending/verification.
- Supabase MCP is configured for the environment but the app itself does not use a database yet.

## Conventions to follow

- Path alias `@/*` → project root.
- Client components declare `"use client"`; data fetching via React Query against `/api/jobs`.
- Match existing Tailwind token usage (`text-text-primary`, `bg-bg-card`, `brand-lime`, `brand-dark`, explicit `dark:` variants).
- Read the relevant `node_modules/next/dist/docs/` guide before writing Next.js framework code.
