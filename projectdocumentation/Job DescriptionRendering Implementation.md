# Job Description (JD) Rendering Implementation

This document details the architectural decisions, tools, and logic used to implement the dynamic, data-driven Job Description rendering system in the application.

## Overview
Previously, the application attempted to parse unstructured job descriptions using Regex to fit them into hardcoded, standardized UI sections (e.g., "Overview", "Responsibilities", "Requirements"). 

This rigid approach failed because ATS (Applicant Tracking Systems) and job boards format descriptions unpredictably. The new implementation relies on **Data-Driven Formatting**, acting as a pure renderer that allows the embedded formatting of the original job description to dictate the final UI structure.

## Tech Stack
- **`react-markdown`**: Converts markdown strings into safe React elements.
- **`remark-gfm`**: Adds support for GitHub Flavored Markdown (tables, strikethrough).
- **`remark-breaks`**: Instructs the parser to respect single newlines (`\n`) as line breaks (`<br>`), preventing walls of text from ATS data dumps.
- **`@tailwindcss/typography`**: Provides the `prose` plugin to deeply stylize raw HTML elements (headings, lists, quotes) generated by the markdown parser, aligning them with the application's design system.

## Implementation Details

### 1. Markdown Pre-Processor (`lib/markdown-utils.ts`)
Since many ATS systems (like Workday or Greenhouse) export messy plain-text rather than true Markdown, we implemented a robust pre-processor function: `formatJobDescriptionToMarkdown`.

This utility runs *before* the text hits `ReactMarkdown` and performs the following sanitizations:
- **Bullet Normalization**: Detects fake unicode bullets (e.g., `·`, `•`, `●`, `▪`, `➢`) often pasted from MS Word and converts them into standard Markdown bullets (`- `).
- **Auto-Heading Generation**: Detects short, standalone, capitalized sentences (e.g., `\n\n What you'll do \n\n`) and automatically wraps them in `###`, upgrading them to proper HTML headings.
- **Inline Bold Keywords**: Identifies capitalized labels ending in a colon (e.g., `Requirements:`) and wraps them in bold syntax (`**Requirements:**`).
- **Spacing Cleanup**: Squashes excessive consecutive newlines (3+) down to 2, preventing broken layouts.

### 2. Rendering Component (`components/JobDescriptionPanel.tsx`)
The `JobDescriptionPanel` component was refactored to remove all standardized structural UI blocks (like the hardcoded "About Company" section). 

Instead, it passes the sanitized text into `<ReactMarkdown>` wrapped in a heavily customized Tailwind Typography container:
```tsx
<div className="
  prose prose-sm md:prose-base max-w-[65ch] xl:max-w-3xl mx-auto md:mx-0
  dark:prose-invert text-text-muted dark:text-[#D1D5DB]
  /* Custom Headings */
  prose-headings:font-heading prose-headings:font-semibold
  ...
">
  <ReactMarkdown remarkPlugins={[remarkGfm, remarkBreaks]}>
    {formatJobDescriptionToMarkdown(job.jobDescription || job.descriptionPlain || "")}
  </ReactMarkdown>
</div>
```

**Styling Enhancements:**
- **Optimal Line Length**: Applied `max-w-[65ch] xl:max-w-3xl` to constrain text width for optimal reading ergonomics.
- **Branded Lists**: Overrode generic black bullets with `marker:text-brand-lime` and adjusted `leading-relaxed` for airy, legible list items.
- **Rich Elements**: Customized blockquotes with a left border (`border-brand-lime`) and background tint, and styled links with `underline-offset-4` and opacity hovers.

### 3. UX Enhancements (Scroll State Reset)
A critical SPA (Single Page Application) bug was fixed where switching between jobs would preserve the scroll position of the previous job. 

We implemented a robust scroll reset mechanism:
- A `useRef` (`scrollContainerRef`) is bound to the main scrollable content container.
- A `useEffect` hook explicitly tracks `job.id`. When the ID changes, it instantly fires `scrollContainerRef.current.scrollTop = 0` and resets the sticky header visibility, guaranteeing a fresh, top-down view for every newly opened job.
